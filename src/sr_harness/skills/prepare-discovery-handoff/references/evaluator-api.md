# Minimal evaluator implementation map

Read this before exploring implementation internals. These are repository interfaces, not a scientific prescription.

- Write a Python file under context.evaluator/ with a DefaultEvaluator subclass (`from sr_harness.evaluator import DefaultEvaluator`). Use a unique class name.
- Class methods: split(cls, context) -> {'train': context_view, 'validation': context_view}; fit(cls, f, y, context) -> fitted engine.Expression; evaluate(cls, f, y, context) -> numeric metric dict. fit_candidate/evaluate_candidate delegate to these by default; override when density and ordinary regression have different semantics.
- context.data is the current data mapping; context.target is the target name; context.args is a namespace, not a dict. context.with_data(sliced_arrays) preserves schema. Slice every aligned active array in source order.
- Custom evaluator execution is in a DATA-ONLY sandbox. Runtime access to workspace files is NOT available. Read auxiliary NPY/contract files during construction with workspace_code_executor, and generate frozen split-index/error metadata as constants in the evaluator source. Generate large constants programmatically, not by typing them into the model response. Check expected dataset dimensions/content fingerprint so constants cannot silently apply to another dataset. Do not turn metadata into scientific predictors to work around the sandbox. Do not try to disable isolation or inspect sandbox internals.
- `engine.evaluate(f, values, parameters=parameter_dict)` evaluates a formula using an explicit parameter assignment. `engine.parameter_values(f)` returns stored parameter values; `engine.bind_parameters(f, parameter_dict)` returns the bound expression. `engine.fit` fits ordinary squared error, not an arbitrary likelihood. A likelihood evaluator must optimize its own train objective (e.g. scipy.optimize.minimize) and bind the fitted parameters. Read the engine-syntax skill for expression details only as needed.
- For a density, evaluate the candidate on both training observations and a support integration grid, using the SAME measure; normalize, enforce positivity, and test quadrature convergence. Optimize using training observations only. Validation reuses those coefficients; integration bounds and selection are frozen from preparation.
- Existing completion probes expect the standard numeric metric keys supplied by `sr_harness.evaluator.utils.regression_metrics(f, observed, predicted)`. For a distribution those regression metrics are incidental interface diagnostics, not scientific scores. Add the actual objective key and select it as ranking_metric. Do not substitute the likelihood value under the name mse. Explain this interface limitation.
- Run validate_evaluator on a constant baseline with the actual file. It now checks the declared split arrays. Separately save semantic self-tests for the custom likelihood/weights and train-only fitting; a constant probe does not exercise optimizer correctness.
- workspace_shell is a restricted command parser: no semicolon chains, pipes, `&&`, or Unix find. Use workspace_code_executor with pathlib for inspecting several files, directories or arrays in one short call.

When an interface question remains, read only sr_harness/evaluator/default_evaluator.py or the needed symbol through read_source. Deliver and test a small working evaluator before expanding diagnostics. Do not spend the whole budget reading implementation internals.
